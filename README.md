## 部署前先做两个决定：装在哪，模型从哪来

OpenClaw 本身免费且开源（MIT 协议，由独立的 OpenClaw Foundation 维护，没有付费层，也没有官方托管服务），所以花钱的环节只有两个：一台常开的机器，一个模型来源。先把这两件事定了，后面全是顺路。

### 装在哪：电脑、Mac Mini 还是 VPS

三个选项，各有明确的适用场景。自己的电脑零成本，但一关机助手就掉线，只适合试用阶段。Mac Mini 安静省电，是被很多人拿来 7×24 挂助手的主机，但要额外添置硬件。VPS 是三者里门槛最低的常开方案——开机在线、自带固定公网地址，RackNerd 在低价年付 VPS 这个细分里正是靠这个吃饭的。OpenClaw 支持 macOS、Linux、Docker 和 WSL2，VPS 场景直接选原生 Linux，不用绕 WSL2。

### 模型从哪来：订阅、API key 或本地模型

2.0 的引导设置会自动检测你已有的 ChatGPT 或 Claude 订阅、现成的 API key，或者本地模型（比如 Ollama），检测到就直接接线，不需要手写配置文件。模型和 agent harness 在 OpenClaw 里是插件，以后想从 Claude 换到 GPT 或者本地模型，改配置即可，其他部分都不用动。

## 在 RackNerd VPS 上部署 OpenClaw：完整命令流程

五步走完，助手就能在聊天软件里应答了。全程只需要一个 SSH 终端，不装面板。

### 第一步：装系统，登录服务器

开通 VPS 后装一个 Ubuntu LTS，Debian 也行。开通邮件里通常会有 IP 和登录信息，本地终端 `ssh root@你的IP` 登进去。Node 环境不用你操心，下一步的官方脚本会按需准备受支持的 Node.js 运行时。

### 第二步：跑官方安装脚本

bash
curl -fsSL https://openclaw.ai/install.sh | bash


这条命令支持 macOS、Linux 和 WSL2。装完后脚本会自动启动 onboarding 向导。

习惯用 npm 管环境的话，可以走包管理路线：先备好 Node 24.16+ 或 26.1+（推荐 26），然后执行 `npm install -g openclaw@latest --allow-scripts=openclaw`。注意这个 `--allow-scripts` 参数要求 npm 12 或 11.16 以上，npm 11.15 及更早的版本要把它去掉。

### 第三步：完成 onboarding，装上守护进程

向导会验证模型访问、创建工作区并配置 Gateway。用 npm 直接装的包，务必用这条命令开始引导：

bash
openclaw onboard --install-daemon


`--install-daemon` 会把 Gateway 装成守护进程，让它在后台常驻，而不是绑在你当前的 SSH 会话上。服务器部署里这一步别省，SSH 断了助手还活着，靠的就是它。

### 第四步：确认状态，打开控制台

bash
openclaw gateway status
openclaw dashboard


第一条看 Gateway 是否在线，第二条打开浏览器里的 Control UI，发条消息确认助手正常回话。2.0 把会话挪到了 SQLite 上，历史、记忆和上下文重启后还在——对 VPS 来说这点很实际，服务器重启不等于聊天记录清零。

### 第五步：把聊天渠道接进来

渠道配置跟着官方文档的 Channels 部分走，Telegram、WhatsApp、Discord、Slack、飞书、微信这些主流渠道都有接入。有一点提前说：凡是能发私信的渠道，陌生发件人默认会被挡在配对流程外面，你收到配对请求后手动批准：

bash
openclaw pairing approve <channel> <code>


第一次接渠道时看到“有人想配对”别慌，那是给陌生人设的门槛，机制在工作才算正常。

## 部署到公网之后，安全清单比家里多几条

同一个 OpenClaw，跑在自己电脑上和跑在有公网 IP 的 VPS 上，安全姿态要差一档。官方安全文档的表述很直接：把每条入站消息都当成不可信输入。落到操作上：

- 能收私信的渠道默认启用配对机制，这个默认行为别关。
- 主会话的工具默认直接跑在宿主机上，除非你配置了沙箱。2.0 的沙箱带细粒度权限，每个技能能访问什么、能干什么，都可以逐项审批。
- 计划把 Gateway 暴露给其他用户、或要从外部访问 Gateway 之前，先把官方的安全指南、暴露 runbook 和沙箱指南过一遍，这三份文档就是为这个场景写的。
- 顺手核对隐私默认值：OpenClaw 默认只做每日一次的版本检查，匿名功能统计是自愿加入的，`update.checkOnStart: false` 可以把两项都关掉。你的状态、记忆和凭据存在这台服务器上，提示词只发给你自己配置的模型提供商。

## 更新、仿冒仓库和其他容易踩的坑

装完只是开始，这几件事知道在前头能省不少时间。

版本节奏很快。OpenClaw 的版本号按周推进，写作时查到的最新 tag 是 v2026.9.6，别把任何一个具体版本号当长期答案，钉版本前去看 Releases 页。

认准官方仓库。热门项目免不了被仿冒，装东西前确认仓库在 `openclaw` 这个组织名下，别从名字相近的个人仓库拿安装包。

别把 Hermes Agent 当成 OpenClaw。这两个项目经常出现在同一批搜索结果里，但完全是两回事：Hermes Agent 由 Nous Research 发布，用 Python 写的，配置文件的路径和格式都不一样，两边的配置互相粘贴不过去。

想自己编译源码，注意仓库是 pnpm workspace，在仓库根目录直接 `npm install` 是不被支持的。标准流程是：

bash
git clone https://github.com/openclaw/openclaw.git
cd openclaw
pnpm install
pnpm build
pnpm ui:build


从 Clawdbot 或 Moltbot 迁移过来的老用户，走官方迁移指南，实操基本是重命名配置文件加更新镜像 tag。Docker 和 Nix 部署路径在安装指南里有单独章节，适合想把环境隔干净的人。

## 常见问题

### OpenClaw 本身要花钱吗？

不要。核心开源、MIT 协议，没有付费层、托管服务，也没有什么官方 token。真正的开销是两块：一台常开的机器，和模型费用（订阅或 API）。

### 整个部署流程要花多久？

官方 quick start 的口径是五分钟左右：一条命令、跟着向导选模型、打开 Control UI。第一次接聊天渠道会另外花些时间，主要看渠道的账号准备。

### 1GB 内存的 VPS 真的够吗？

模型走云端时基本够。网关是个 Node.js 进程，内存压力主要来自会话和工具执行，不在模型推理上；想在服务器上跑本地模型是另一回事，对内存和 CPU 的要求远超网关本身。拿不准就👉 [看看 RackNerd 各档位当前的价格](https://bit.ly/my-rn)，先小后大。

### 必须买一台 Mac Mini 吗？

不必须。Mac Mini 常被推荐是因为安静省电，但 OpenClaw 在 macOS、Linux、Docker 和 WSL2 上都能跑，手头已有的机器或一台 VPS 都可以。

### 已有的 ChatGPT 或 Claude 订阅能直接用吗？

能。2.0 的引导设置会自动检测已有订阅、API key 或本地模型，检测到就直接接线，不用手改配置文件。

### 之前用的是 Clawdbot 或 Moltbot，怎么迁？

走官方迁移指南，实操基本是重命名配置文件和更新镜像 tag，工作量不大。
